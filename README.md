# TENNECO Improvement — เว็บแอปแจ้งงานปรับปรุง

เว็บแอปสำหรับมือถือ ให้พนักงานถ่ายรูป **Before** + แจ้งสิ่งที่ต้องแก้ไข → ผู้ดูแล
ตรวจสอบ / อนุมัติ / อัปเดตสถานะโต้ตอบ → ถ่ายรูป **After** แล้วปิดงาน
พร้อมหน้ารายงานสรุปและ **Export Excel ที่ฝังรูปภาพจริง**

ข้อมูลทั้งหมดอยู่บน **ฐานข้อมูลกลาง** — ทุกเครื่องเห็นข้อมูลชุดเดียวกัน
สิ่งที่แต่ละคนทำได้ขึ้นกับ **สิทธิ์** ที่ Super Admin กำหนดไว้ในหน้าตั้งค่า

## เข้าสู่ระบบ

ล็อกอินด้วย **รหัสพนักงาน** อย่างเดียว (ไม่มีรหัสผ่าน — แนวเดียวกับระบบ PSIF)
รายชื่อคัดลอกมาจากฐานข้อมูล PSIF และกดอัปเดตใหม่ได้ตลอดที่ **ตั้งค่า → ดึงรายชื่อพนักงานจาก PSIF**

- ใส่ขีดหรือไม่ใส่ก็ได้ — `G260` เข้าได้เท่ากับ `G-260`
- พนักงานที่ถูกปิดใช้งานจะล็อกอินไม่ได้
- เครื่องจำผู้ใช้ไว้ เปิดแอปครั้งต่อไปเข้าได้เลย (ยืนยันกับเซิร์ฟเวอร์ทุกครั้งที่เปิด)

## สิทธิ์การใช้งาน 4 ระดับ

ตั้งที่ **ตั้งค่า → ข้อมูลพนักงาน & สิทธิ์การใช้งาน** (เฉพาะ Super Admin)

| สิทธิ์ | ทำอะไรได้ |
|---|---|
| **พนักงาน** (`user`) | แจ้งงาน · เห็นงานทุกงานทั้งโรงงาน · ตอบกลับได้เฉพาะงานที่ตัวเองแจ้ง |
| **หัวหน้า / Manager** (`manager`) | เพิ่มจากพนักงาน: อนุมัติ / ไม่อนุมัติ / ตอบกลับ / แนบรูป After / ปิดงาน **เฉพาะงานในแผนกตัวเอง** |
| **Admin Improvement** (`improve_admin`) | จัดการได้ทุกงาน ทุกแผนก |
| **Super Admin** (`admin`) | ทุกอย่าง + เมนูตั้งค่า (กำหนดสิทธิ์ · จัดการพื้นที่ · ดึงรายชื่อจาก PSIF · ลบงาน) |

ขอบเขตของ Manager เทียบจาก **แผนกของผู้แจ้ง ณ วันที่แจ้ง** ที่เก็บไว้ในงาน (คอลัมน์ `dept`)
ไม่ใช่พื้นที่ที่เลือกในฟอร์ม — ย้ายแผนกภายหลังจึงไม่ทำให้ประวัติงานเก่าเปลี่ยนเจ้าของ

> การตรวจสิทธิ์จริงอยู่ที่ **ฝั่งเซิร์ฟเวอร์** ทุกจุด — หน้าเว็บแค่ซ่อน/แสดงปุ่มให้ตรงกัน
> `role` อ่านจากตาราง `employees` เสมอ ไม่เชื่อค่าที่ client ส่งมา

## ฟังก์ชัน

### 1. บันทึกงาน (ปุ่มกลาง)

- **บังคับ** ถ่ายรูป Before อย่างน้อย 1 รูป (สูงสุด 4 รูป) — เปิดกล้องผ่านแอปโดยตรง
- **บังคับ** เลือกพื้นที่ · ระบุเครื่องจักร (มีรายการเดิมให้เลือกอัตโนมัติ) · หัวข้อ · รายละเอียด
- รูปถูกย่อในเครื่องก่อน แล้วอัปโหลดขึ้น R2 ตอนกดส่ง
- ได้รหัสงานอัตโนมัติ เช่น `IMP-6909-01` (พ.ศ. 2 หลัก + เดือน + ลำดับในเดือน ตามเวลาไทย)
- **กันบันทึกซ้ำ** — กดส่งแล้วเน็ตหลุด กดใหม่ได้งานเดิม ไม่เกิดงานซ้ำ (`request_id`)
- **เก็บร่างอัตโนมัติ** — กรอกค้างแล้วปิดแอป กลับมาเปิดใหม่ข้อมูลยังอยู่
- ระบบแจ้งเตือนผู้ดูแลทันที (Admin Improvement / Super Admin ทุกคน + Manager ของแผนกผู้แจ้ง)

### 2. รายการงาน (เมนูซ้าย)

- แกลเลอรีรูป 2 คอลัมน์ · ป้ายสถานะบนรูป · ชื่อผู้แจ้งและวันที่
- กรองด่วน: ทั้งหมด / งานของฉัน / รอตรวจสอบ / กำลังดำเนินการ / จบงาน / ไม่อนุมัติ
- ตัวกรองเต็ม: ค้นหาข้อความ · สถานะ (เลือกหลายอัน) · พื้นที่ · เครื่องจักร · ช่วงวันที่ · การเรียงลำดับ
- กดที่รูปเพื่อเปิดรายละเอียด: รูป Before / After (กดขยายได้) · ข้อมูลงาน · **ไทม์ไลน์ทั้งหมด**
- งานที่จบแล้วแสดงรูป Before / After **วางข้างกัน**

### 3. รายงาน (เมนูขวา)

- ช่วงข้อมูล 30 / 90 วัน / ทั้งหมด
- KPI: อัตราปิดงาน (วงแหวน) · รอตรวจสอบ · กำลังดำเนินการ · จบงาน · ไม่อนุมัติ · เวลาเฉลี่ยต่องาน
- แถบสัดส่วนสถานะรวม + สรุปแยกตามพื้นที่ (แสดงครบทุกพื้นที่เสมอ)
- แนวโน้มรายเดือน (แจ้งเข้า vs ปิดได้) · ปุ่ม **Export รายงาน Excel**

### 4. ฝั่งผู้ดูแล

- กระดิ่งแจ้งเตือนขึ้นตัวเลขงานใหม่ (ดึงจากเซิร์ฟเวอร์ทุก 60 วินาที) + จุดแดงบนเมนูรายการงาน
- **อนุมัติ · เริ่มดำเนินการ** และ **ไม่อนุมัติ** (ต้องระบุเหตุผล — เหตุผลไปแสดงให้ผู้แจ้งเห็น)
- **พิมพ์ตอบโต้ผู้ส่ง** ได้อิสระ พร้อมข้อความสำเร็จรูปให้กดเลือก
- **ถ่ายรูป After** แล้ว **ปิดงาน** — ถ้ายังไม่มีรูป After เซิร์ฟเวอร์จะไม่ยอมให้ปิด
- เปิดงานที่ปิดไปแล้วขึ้นมาใหม่ได้

## ไฟล์ Excel ที่ export ออกมา (3 ชีต)

**ชีต 1 — สรุปภาพรวม** · หัวรายงาน 3 แถบสีแบรนด์ · KPI 9 ตัวแบบการ์ด · ตารางสรุปตามพื้นที่พร้อมแถบความคืบหน้า · ตารางคำอธิบายสถานะ

**ชีต 2 — รายการงาน** · 14 คอลัมน์ + ข้อความล่าสุดจากผู้ดูแล + ระยะเวลาที่ใช้ · ตรึงหัวตารางและ 2 คอลัมน์แรก · AutoFilter · ระบายสีเซลล์สถานะ · **ฝังรูป Before / After ลงในเซลล์จริง**

**ชีต 3 — เปรียบเทียบ Before-After** · เฉพาะงานที่ปิดแล้ว บล็อกละ 1 งาน พร้อมรูปขนาดใหญ่วางข้างกัน เหมาะกับการพิมพ์เสนอผู้บริหาร

ทุกชีตตั้งค่าการพิมพ์ไว้แล้ว (พอดีหน้ากว้าง · ซ้ำหัวตารางทุกหน้า · เลขหน้าท้ายกระดาษ)
รูปถูกดึงจาก R2 มาแปลงเป็น base64 ก่อนฝัง — งานที่โหลดรูปไม่สำเร็จจะข้ามรูปไป ไฟล์ยังสร้างได้ปกติ

## โครงสร้างไฟล์

```
index.html          โครงหน้าจอทั้งหมด (login + 3 เมนู + ตั้งค่า + sheet ต่าง ๆ)
assets/app.css      ดีไซน์ระบบทั้งหมด (โทนน้ำเงิน–ขาวตามแบรนด์)
assets/app.js       ตรรกะแอป: ล็อกอิน, ฟอร์ม, แกลเลอรี, ตัวกรอง, สถานะ, รายงาน, สิทธิ์
assets/export.js    สร้างไฟล์ Excel ด้วย ExcelJS + ฝังรูป Before/After
worker.js           API ทั้งหมด (Cloudflare Worker)
schema.sql          โครงสร้างฐานข้อมูล D1
wrangler.toml       การผูก D1 / R2 เข้ากับ Worker

```

### ใส่โลโก้จริง

บันทึกไฟล์โลโก้เป็น **`assets/logo.png`** (พื้นหลังโปร่งใส สูงประมาณ 60–100 px)
แอปจะสลับจาก wordmark ที่วาดด้วย CSS มาใช้โลโก้จริงให้อัตโนมัติทั้งหน้า login และแถบบน

## การดูแลระบบ

### แก้ไข API แล้ว deploy ใหม่

```bash
npx wrangler deploy
```

### แก้โครงสร้างฐานข้อมูล

```bash
npx wrangler d1 execute improvement-db --remote --file=./schema.sql
```

(ไฟล์เขียนแบบ `IF NOT EXISTS` ทั้งหมด รันซ้ำได้ไม่พัง)

### ทดสอบหน้าเว็บในเครื่อง

```bash
node server.js
```

เปิด `http://localhost:5599` บนคอม หรือ `http://<IP ของคอม>:5599` บนมือถือที่อยู่ Wi-Fi เดียวกัน
(หน้าเว็บในเครื่องยิงไปที่ API ตัวจริงบน Cloudflare — เห็นข้อมูลชุดเดียวกับที่ใช้งานจริง)

### เปลี่ยนที่อยู่เซิร์ฟเวอร์

หน้า **ตั้งค่า → การเชื่อมต่อ** เปลี่ยนได้เฉพาะเครื่องนั้น (เก็บใน localStorage)
ถ้าจะเปลี่ยนถาวรทั้งระบบ แก้ `DEFAULT_API` ที่หัวไฟล์ `assets/app.js`

## รายการ API

| Method | Path | สิทธิ์ | ทำอะไร |
|---|---|---|---|
| GET | `/health` | — | ตรวจว่า API ยังทำงาน |
| POST | `/login` | — | ล็อกอินด้วยรหัสพนักงาน |
| GET | `/bootstrap` | — | พื้นที่ · เครื่องจักร · จำนวนงานค้าง · ตัวตนผู้เรียก |
| GET | `/jobs` | ทุกคน | รายการงาน (กรองด้วย query string ได้) |
| GET | `/jobs/:id` | ทุกคน | รายละเอียด + รูป + ไทม์ไลน์ |
| POST | `/jobs` | ทุกคน | แจ้งงานใหม่ |
| PATCH | `/jobs/:id` | ผู้ดูแลงานนั้น | `approve` / `reject` / `close` / `reopen` |
| POST | `/jobs/:id/note` | ผู้แจ้ง หรือ ผู้ดูแลงานนั้น | ส่งข้อความตอบโต้ |
| POST | `/jobs/:id/photos` | ผู้ดูแลงานนั้น | แนบรูป After |
| DELETE | `/jobs/:id` | Super Admin | ลบงาน + ลบรูปใน R2 |
| POST | `/photo` | ล็อกอินแล้ว | อัปโหลดรูปขึ้น R2 → คืน key |
| GET | `/photo/<key>` | — | เสิร์ฟรูปจาก R2 |
| GET | `/employees` | manager ขึ้นไป | รายชื่อ + สิทธิ์ |
| PATCH | `/employees/:id` | Super Admin | เปลี่ยนสิทธิ์ / เปิด-ปิดการใช้งาน |
| POST | `/employees/sync` | Super Admin | ดึงรายชื่อจาก PSIF |
| GET/POST/DELETE | `/areas` | อ่าน: ทุกคน · แก้: Super Admin | จัดการพื้นที่ |
| GET/POST | `/notifications` | ล็อกอินแล้ว | แจ้งเตือนของตัวเอง / ทำเครื่องหมายอ่านแล้ว |

หมายเหตุเรื่องการ sync: อัปเดต **ชื่อ / แผนก / สถานะใช้งาน** จาก PSIF
แต่ **ไม่แตะสิทธิ์** ที่ตั้งไว้ในระบบนี้ (คนละชุดกับ role ของ PSIF)
รหัสที่ขึ้นต้น `RESIGNED-` ใน PSIF เป็นช่องเก็บข้อมูลคนลาออก ไม่ใช่คน จึงถูกข้าม

## รอบตรวจ UI/UX (ทำแล้ว)

**§1 Accessibility** — คอนทราสต์ผ่าน 4.5:1 ทุกจุดที่ตรวจ · ปุ่มไอคอนมีชื่อเรียกครบ · รูปมีคำบรรยาย ·
sheet เป็น dialog จริง (role/aria-modal) + ซ่อนพื้นหลังจาก screen reader + คืนโฟกัสเดิมเมื่อปิด ·
toast/แจ้งเตือนประกาศผ่าน aria-live · ข้อความ error เป็น role="alert" ผูกกับช่องกรอก · โฟกัสคีย์บอร์ดมีกรอบชัดเจน

**§2 Touch** — เป้าแตะ ≥44px ทุกปุ่ม · ชิปเว้นระยะ 8px · `touch-action: manipulation` ตัดดีเลย์ 300ms

**§5 Layout** — ไม่ปิดการซูมด้วยนิ้ว · ช่องกรอก 16px กัน iOS ซูมเองตอนโฟกัส · รองรับจอแนวนอน/จอเตี้ย

**§7 Animation** — รองรับ `prefers-reduced-motion`

**§8 Forms** — ตรวจตอนออกจากช่อง (ไม่ขึ้นแดงระหว่างพิมพ์) · ส่งไม่ผ่านแล้วเลื่อน+โฟกัสไปช่องแรกที่ผิด · เก็บร่างอัตโนมัติ

**§9 Navigation** — ปุ่ม Back ของมือถือปิดหน้าต่างซ้อนแทนการเด้งออกจากแอป (บนคอมกด Esc ได้)

**§10 Charts** — กราฟแนวโน้มมีคำอธิบายสี + ตัวเลขกำกับหัวแท่ง + สรุปเป็นข้อความสำหรับ screen reader
